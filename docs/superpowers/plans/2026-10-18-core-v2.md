# v2 内核实现计划（推进核 + Mod 宿主，两个事件的最小内容）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在无共同祖先的 `v2` 分支上从零实现一个确定性推进核 + Mod 宿主，并用「无事发生 / 死亡」两个事件在浏览器里跑完一局。

**Architecture:** `packages/core` 零依赖：RNG 种子化、state 只存 JSON 且写入可追踪、emit 是唯一输出通道、`advance()` 按 order→requires→id 的顺序串行 await 三段钩子。内容全部在 `packages/mods/base`，引擎不认识任何游戏概念。

**Tech Stack:** ESM、Node 22+（`node --test`、`node:crypto`）、原生 HTML/JS（无构建、无 npm 依赖）。

**Spec:** `docs/superpowers/specs/2026-10-18-core-design.md`

## Global Constraints

- `packages/core` **零运行时依赖**；测试用 `node --test`（不用 vitest）。
- state 只能存 JSON 可序列化值：函数 / undefined / NaN / Infinity / BigInt / 循环引用一律抛错。
- 每年严格串行 `await`；同一 seed + 同一 mod 集合 ⇒ 同一 `state + 事件流` hash。
- 事件 entry 固定形状：`{kind, year, modId, text?, payload?, delta?}`。
- `packages/core/src` 非注释代码中不得出现：`constitution` `intelligence` `strength` `charm` `talent` `achievement` `grade`。
- 前端零依赖：`index.html` + `app.js`，用原生 ESM 直接 import，`python -m http.server` 打开。
- 提交信息用中文，`feat:` / `test:` / `docs:` 前缀。

## Review Focus

- **空 mod 列表**：跑 100 年仍产出 100 条 `year:end`，不崩（`clock` 循环依赖 mods 长度的时间边界）。
- **钩子抛错**：单个 mod 崩了，这一局继续跑完而不是卡死，且 `core:error` 里能看出是谁。
- **非 JSON 值写入**：`ctx.set('x', () => 1)` 必须立刻抛错，而不是静默存成 `undefined`。
- **同年同路径双写**：两个 mod 写同一 key 时要能报出来，否则"互相踩"问题原样搬进 v2。
- **快照隔离**：`snapshot()` 之后再改 state，快照不能跟着变（否则黄金 hash 测试假通过）。
- **结束后再推进**：`advance()` 在已结束后必须是幂等的空操作，不能继续加年。
